## 준비 점검 결과

- 카카오 콘솔: 기존 Common Plant 비즈앱, 사용자 Editor 역할 확인. 로그인 ON, 이메일 `account_email` 필수 동의·수집, 닉네임 필수·사진 선택 동의 확인.
- 비어 있던 네이티브 앱 키의 Android 패키지 `com.plant.common`, Debug 키 해시, iOS Bundle ID `com.commonplant.umc`를 등록·저장했다. 새 앱이나 새 키는 생성하지 않았다.
- 사용자가 네이티브 키를 Git 제외·권한 600 파일에 저장했다. 키 원문은 문서·로그에 기록하지 않았다.
- 첫 Android 빌드의 격리된 XDG 설정 경로가 별도 Debug 인증서를 만들었다. 기존 Mac 인증서를 로컬 설정에 복사하여 재빌드했고 APK에서 제공받은 Debug 키 해시와 일치를 확인했다. APK callback과 Dart 설정 키의 일치도 확인했다.
- iOS는 Git 제외 plist/xcconfig를 만들어 callback·개인 Team·로컬 네트워크 설정을 주입한다. 원본 Xcode 프로젝트와 Apple 구성은 변경하지 않는다.
- 사용자 추가 규칙: 백엔드는 로컬 수정·실행 가능, 원격 push·PR·이슈/파일 변경 등 저장소 반영은 절대 금지. 원본 백엔드와 QA worktree의 Git 제외 `AGENTS.md`에 저장했다.
- PostgreSQL 15·Garage 2.3.0·public proxy를 로컬 compose로 실행했다. 백엔드는 JDK 17, `local`, `ddl-auto: update`, 별도 랜덤 JWT/DB/스토리지 비밀값으로 실행하며 로그인 상세·SQL 출력은 껐다. 액세스 로그에는 메서드·경로·HTTP 상태·처리 시간만 남긴다.
- 로컬 health HTTP 200. 실제 카카오 사용자 인증 성공과는 구분한다.

공식 설정 근거: [Kakao Flutter 시작하기](https://developers.kakao.com/docs/ko/flutter/getting-started), [Kakao 로그인 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite). SDK 1.10.0의 기존 callback activity를 유지하며 최신 2.x 예제의 class 이름을 그대로 옮기지 않는다.

## Android 실제 인증과 사진 결과

- 사용자 입력과 동의 후 `POST /auth/login` 200, `POST /auth/register` 200을 확인했다. 빈 로컬 DB에 활성 카카오 사용자 1명이 생성됐다.
- 같은 계정으로 다시 로그인해 홈과 마이를 열었다. `GET /users`와 `GET /plants`가 200이었다. 두 인증 저장 키가 생성됐고 앱 완전 종료 후 별도 로그인 없이 저장 세션과 서버 조회가 복원됐다.
- 앱 설정의 로그아웃으로 두 인증 저장 키가 제거됐다. 동일 계정 카카오 재로그인과 `GET /users` 200을 확인했다.
- 시스템 사진 선택기를 뒤로가기로 닫고 다시 열어 테스트 JPEG를 선택했다. 미리보기와 사진만 바꾸는 수정 버튼 활성화를 확인했다. 오프라인 제출에서는 네트워크 오류 안내와 사진 선택 상태가 유지됐으며, 연결 복구 후 같은 사진을 다시 제출해 `PUT /users` 200을 받았다.
- DB에 사용자 사진 참조와 동일 크기 이미지 1개가 생성됐다. 앱 프로세스를 완전히 종료한 뒤 새 `GET /users` 200 및 사진 표시를 확인했다. Garage public proxy의 사진 GET은 200이었다.
- 홈 자료 조회 지연에서 스피너, 빈 계정에서 장소 추가 및 식물 추가 비활성, 오프라인 재실행에서 조회 오류와 재시도 문구를 확인했다. Android IME 편집 컨트롤은 화면에서 확인했으며 가상 키보드 전체 표시 상태는 추가 확인이 필요하다.

## iPhone 설치 및 시뮬레이터

- iPhone 16 Pro에 로컬 Debug 빌드를 설치했다. 처음은 잠금·개발자 프로필 신뢰 문제로 실행 요청이 거절됐다. 사용자 설정 후 Mac의 실행 요청은 성공했으나 iPhone에서 앱 화면을 열 수 없다는 사용자 확인을 받았다.
- 사용자의 요청으로 iPhone 17 Pro (iOS 26.4.1) 시뮬레이터에서 검증을 이어간다. Xcode 27.2에서 시뮬레이터 화면은 Device Hub로 확인한다. Flutter의 프레임워크 아키텍처 처리 오류를 Git 제외 xcconfig의 arm64 시뮬레이터 설정으로 해소했다.
- 시뮬레이터에 App을 설치하고 온보딩과 카카오 인증 창을 열었다. 시뮬레이터는 `127.0.0.1:8080`을 사용한다. 계정 입력과 동의는 사용자에게 넘겼다.

## iPhone 시뮬레이터 실제 인증과 사진 결과

- 사용자가 iPhone 17 Pro 시뮬레이터에서 카카오에 직접 로그인했다. `POST /auth/login`, `GET /users`, `GET /plants`가 모두 200이었으며 정원 빈 상태와 마이의 기존 프로필 사진이 표시됐다.
- 사진 선택기를 닫아 취소를 확인한 뒤 테스트 JPEG를 다시 선택했다. 미리보기와 수정 버튼 활성화를 확인했다. 소프트웨어 키보드를 표시했을 때 닉네임 입력과 수정 버튼이 키보드 위에 보이고 버튼을 누를 수 있었다.
- `PUT /users` 200 이후 `simctl terminate` 후 새 프로세스로 실행했다. 인증 안내 없이 홈이 표시됐고 새 `GET /users` 200과 Garage 사진 GET 200으로 마이의 사진이 다시 표시됐다. 회원 정보 수정의 뒤로가기 버튼으로 마이 복귀를 확인했다.
- 실기기에서는 설치 이후 앱 화면을 열 수 없다는 사용자 확인까지 기록했다. iOS 서버 인증과 UI 결과의 실행 기기는 iPhone 시뮬레이터다.

## 약관 제출 후 닉네임 오류 #327

약관 화면에서 가입을 제출해 서버의 닉네임 오류를 받으면, 값을 수정할 수 있는 프로필 화면으로 돌아가 기존 필드 오류 안내를 표시한다. 닉네임·사진 초안·동의 상태를 보존하고, 입력값과 무관한 서버 장애는 약관 화면에서 다시 시도할 수 있게 한다.

1. 실제 앱 라우터와 모의 가입 API를 사용해 서버의 `name` 오류를 재현한다.
2. 약관의 가입 실패 분기에서 프로필 폼으로 복귀한다. 수정 후 가입 완료와 일반 서버 장애 재시도를 검증한다.
3. FVM 포맷·정적 분석·전체 테스트를 실행한다.

- `b59f740`에서 약관의 실패 분기와 가입 회귀 테스트를 수정했다. 수정 전 닉네임 필드 오류 시나리오는 실패했다. 수정 후 약관·로그인 대상 테스트 21개, 전체 885개가 통과했고 기존 골든 1개는 건너뛰었다.
- FVM 포맷 361개 파일, 정적 분석 및 diff 검사를 통과했다.

### 가입 닉네임 입력 검증 보완

닉네임이 현재 가입 폼의 2~10자 길이와 서버의 한글·영문·공백 규칙을 만족하는지 한곳에서 확인한다. 입력칸에서 처음 포커스가 벗어나면 오류를 표시하고, 이후 수정하면 즉시 갱신한다. 완료 버튼도 같은 형식 검증 결과로 활성화한다.

1. 입력과 제출 상태를 공통 검사로 연결하고, 형식 검사와 중복 여부 확인을 혼동할 수 있는 성공 문구를 제거한다.
2. 포커스 이탈 전후와 수정 후 버튼 상태를 확인한다. 서버가 별도로 닉네임 필드 오류를 반환할 때의 복귀와 재시도도 다시 검증한다.

# 장소 좌표 누락 시 판교역 날씨 #307

> **정책 철회:** #309 사용자 결정으로 판교역 기본 조회는 제거했다. 현재 정책은 [장소 좌표 없는 날씨 조회 차단](place-weather-unavailable-309.md)이다. 아래 기본 위치 구현·출시 검토는 당시 이력이며 현행 동작이 아니다. 실제 공공데이터 검증과 예보 응답 시각 수정은 유효한 검증 기록으로 유지한다.

## 구현 전 기록

2026-09-21 사용자 요청: 저장한 공공데이터 키로 테스트할 수 있도록 장소 API의 좌표가 없으면 **경기도 성남 판교역**을 기본 위치로 조회한다. #306의 좌표 없음 → 준비 중 정책을 이 요청으로 변경한다. 임시 `xPosition`·`yPosition`의 API 계약은 여전히 추측하지 않는다.

## 위치 근거와 적용 조건

- [판교역 위치](https://ko.wikipedia.org/wiki/판교역_(성남)): 위도 37.3947611, 경도 127.1111361.
- [기상청 날씨누리 공식 좌표 변환](https://www.weather.go.kr/w/resources/js/fn.js)의 `convertDfsGrid("toXY", latitude, longitude)`와 동일한 LCC 5km 격자 계산 결과 **nx=62, ny=123**. 앱에는 확인된 격자만 상수로 두며 범용 위경도 변환은 추가하지 않는다.
- API 모드에서 `placeWeatherGridProvider(placeId)`가 유효한 격자를 제공하면 우선 사용한다. null이면 위 판교역 격자로 조회한다. 현재 backend 계약 미확정으로 이 공급 지점은 null이므로 판교역을 사용한다.
- 기본값을 사용할 때 모든 조회 상태에 `판교역 기준`을 표시한다. 실제 장소 격자가 우연히 판교역과 같더라도 공급 값이 있으면 기본값 안내를 표시하지 않는다.
- 로컬 모드는 기존 준비 상태와 호출 0회를 유지한다. 키 누락·인증 오류·날씨 API 실패는 가짜 값으로 대체하지 않고 기존 실패/재호출 처리에 따른다.
- 조회와 수동 재시도는 같은 위치 선택 규칙을 사용한다. 기존 시도별 5초, 최초 포함 총 3회, 요청 취소·계정 격리를 유지한다.
- 장소 상세 자체의 오류/권한 오류를 성공으로 바꾸지 않는다. 잘못된 좌표 타입·좌표계·파싱 오류의 정책은 백엔드 계약 확정 시 구분한다.

## 키와 실제 검증

실제 호출에서 두 endpoint 모두 HTTP 200 / resultCode `00`을 받았다. 초단기예보 요청 `20260921/0030`의 실제 응답은 `baseDate=20260921`, `baseTime=0000`, 66개 항목이었다. 기존 mapper가 요청 시각과 완전히 같아야 한다고 검사해 정상 응답을 거절했다. [공공데이터포털](https://www.data.go.kr/data/15084084/openapi.do)의 `2607.zip` 내 공식 가이드도 요청 HH30·응답 설명 HH00과 XML 예제 HH30을 함께 제시한다. 이 두 형식만 같은 날짜·시간대에서 허용하고 모든 항목의 기준시각 일치를 검증한다. 다른 날짜·시간대·실황 시각 불일치는 계속 거절하며 실제 응답의 발표시각으로 예보 유효 범위를 검사·보존한다.

키는 원본 저장소의 git 제외 `env/local.weather.json`에서 읽고 값·요청 URL을 출력/커밋하지 않는다. 새 worktree 실행에서도 이 파일의 절대 경로를 `--dart-define-from-file`로 전달할 수 있다. 키를 파일에 저장한 것만으로 기존 실행 앱에 적용되지는 않으므로 실행 인자를 포함해 앱을 다시 시작해야 한다.

실제 공공데이터 응답 확인과 자동 테스트, 휴대폰 화면/소셜 로그인/사진 업로드 QA는 각각 구분해 기록한다. PR 병합은 사용자가 진행한다.

### 실제 확인 결과

- 2026-09-21 01:21 KST, 실제 구현의 기본 위치 선택 → 날씨 Provider → repository → 전용 Dio → 두 공공데이터 endpoint → mapper로 검증했다. 임시 검증 파일은 저장소 밖에 두었으며 일반 테스트/CI는 실제 키와 네트워크를 사용하지 않는다.
- 실황·예보 HTTP 200 / resultCode `00`, 기본 격자 `(62, 123)`, 약 160ms에 성공했다. 실황 8개·예보 66개 항목을 검증했다.
- 기온 **18.7℃**, 습도 **100%**, 강수 없음, 가까운 하늘상태 **맑음 예보**. 관측 9/21 01:00, 응답 예보 발표 00:00, 선택된 하늘상태 예보 02:00 KST. 이 값은 당시 관측·예보이며 고정 fixture로 앱에 넣지 않았다.
- dev Swagger 재확인은 HTTP 403으로 응답 본문을 확인하지 못했다. 좌표 필드 계약은 미확정 상태를 유지한다.
- 실제 휴대폰 표시, 실제 장소 좌표, 네트워크 장애 상태에서의 실기기 재호출은 아직 검증하지 않았다. 5초·3회·재호출은 제어된 응답의 자동 테스트로 확인했다. 소셜 로그인·사진 업로드 QA는 기존 #293/#295에 남긴다.

### 앱 테스트 실행

이 기능 브랜치/worktree에서 기존 소셜 로그인 실행 설정을 유지하고 아래 날씨 설정 인자를 추가해 다시 실행한다. `dart-define`은 실행/빌드 시 적용되므로 hot reload만으로 새 키가 들어가지 않는다.

```bash
fvm flutter run \
  --dart-define=COMMONPLANT_USE_API=true \
  --dart-define=COMMONPLANT_API_BASE_URL=https://commonplant-dev.okbear.dev/api/v1 \
  --dart-define-from-file=/Users/ywkim/SideProjects/v3_CommonPlant_Frontend_Repo/env/local.weather.json
```

개인 팀 iOS 설정은 원본 작업 폴더에 보존되어 있으며 이 worktree에 복사하거나 커밋하지 않았다. 개인 팀 서명이 필요한 기기 실행은 해당 로컬 설정이 있는 작업 폴더에 이 PR을 반영한 뒤 진행한다.

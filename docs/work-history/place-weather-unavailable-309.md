# 장소 좌표 없는 날씨 조회 차단 #309

## 구현 전 결정

2026-09-21 사용자 정책 변경: **장소 주소에 대응하는 확인된 좌표로만 날씨를 조회**한다. 주소/좌표가 없으면 `날씨 정보를 조회할 수 없어요`를 표시한다. #307의 판교역 기본 위치 정책은 철회한다. 기존 OPEN PR #308을 이 최종 범위로 갱신하며 실제 응답으로 발견한 예보 기준시각 수정은 유지한다.

기상청 API는 주소 문자열이 아닌 격자 `nx`/`ny`를 받는다. 주소 → 좌표의 담당과 계약이 확인되기 전에는 새 주소 검색·지오코딩 서비스나 임시 JSON 필드를 추가하지 않는다. 화면에 주소가 있다는 사실만으로 날씨 조회 가능 상태로 보지 않는다.

## 상태별 기준

| 상황 | 조회 및 화면 |
| --- | --- |
| 장소 주소에 대응하는 유효한 격자 있음 | 해당 격자로 실황·예보 조회. 기존 시도별 5초·총 3회 유지 |
| 주소 없음 / 대응 좌표 없음 / 좌표 계약 미연결 | 네트워크 호출 0회, 조회 불가 안내, 재호출 버튼 없음 |
| 유효한 좌표로 실제 요청했지만 실패 | 기존 날씨 위치에 오류와 재호출 아이콘 표시 |
| 장소 좌표가 사라짐 | 기존 조회 취소, 이전 날씨 숨김, 늦은 결과 무시 |
| 좌표가 새로 확인됨 / 변경됨 | 해당 좌표의 새 요청으로 전환 |
| 로컬 모드 | 네트워크 호출 0회, 조회 불가 안내 |

현재 `placeWeatherGridProvider`는 backend 필드·좌표계 계약 미확정으로 null을 반환한다. 따라서 앱에 주소 문자열이 있어도 당장은 조회 불가 안내가 정상이다. 주소 문자열을 임의로 파싱하거나 현재 위치·고정 지역으로 대체하지 않는다.

## 검증 범위

#307에서 실제 키로 판교역 격자의 공공데이터 응답과 예보 기준시각 차이를 확인한 기록은 유지한다. 그 좌표는 당시 API 검증 입력이며 현재 앱의 기본 위치가 아니다. 이번 수정은 키·네트워크 없는 자동 회귀 검증으로 확인한다. 실제 장소 좌표·휴대폰 화면·소셜 로그인·사진 업로드 QA를 완료 처리하지 않는다.
